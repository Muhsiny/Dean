# Tests

## Test 1 - One-click public entry opens the newsroom [sanity]
Viewport: desktop (1280x800)
Covers: one-click anonymous entry, browser-stable visitor identity, consolidated public bootstrap for visitor/feed/settings, entry-click tracking, successful-entry tracking, seven-language selector, immediate PWA install suggestion when the browser declares the app installable, fast repeat navigation through the PWA shell cache
Description: Verifies a public visitor enters without email, password, verification code, popup or a second confirmation.
Steps:
1. Navigate to the app with no active visitor session
2. Confirm the Language selector contains دری, پښتو, English, العربية, اردو, Türkçe and Français
3. Select دری and confirm the screen shows one visible «ورود» button and no email, password, verification-code or «خیر» control
4. Press «ورود» once
5. Confirm the newsroom opens without any authentication popup, refresh once, and confirm the existing session returns directly to a populated newsroom without reopening the entry gate
6. In an installable browser, confirm SAYEH NEWS surfaces its install suggestion and that the «دانلود اپ» control no longer fails because the visitor is anonymous
Expected: One click creates the anonymous visitor session and opens the newsroom; subsequent session startup receives visitor, feed and settings through one consolidated bootstrap rather than serial public requests, repeat navigation can use the cached PWA shell while refreshing in the background, the click and successful entry remain separately countable in owner analytics, and an eligible browser can proceed to the real PWA installation flow without an email-auth analytics error.

Covers: Home duplicate suppression, repeated lead-image signal, distinct-story preservation

Steps:
1. Use an authenticated QA visitor session to reach Home and keep the search field completely empty
2. Inspect the visible news cards and confirm there are not two cards that reuse the same lead image while also referring to the same actor/place/event, even when their titles are rewritten differently
3. Confirm distinct stories with different event meaning remain visible rather than being removed merely for sharing a source
4. Open one visible story and then close it, confirming the feed remains populated and usable with the search field still empty
Expected: With no search filter active, the newsroom feed remains populated, keeps one card per true duplicate event, preserves distinct stories, and remains usable after opening and closing a story.
